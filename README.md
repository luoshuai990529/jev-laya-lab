# Jev × Laya 决策实验台

**Jev 和 Laya 决策模型对比实验。** 导入自己的选择问题，用同一批样本比较选择正确率、答案分布和完成整批任务的总耗时。仓库名：`jev-laya-lab`。

应用在本机运行，使用你的 Jev API Key 或本地 / 自托管 Laya 服务。摩托车科目一、科目四题库作为默认附加测试数据，也可以换成客服路由、运营选择、逻辑判断或其他有标准答案的决策问题。

## 快速开始

安装 **Node.js 22 或更新版本**，在项目目录运行：

```sh
npm start
```

打开 **http://127.0.0.1:4317/**。Node 工作台没有第三方运行依赖，不需要先执行 `npm install`。macOS 也可双击 `start.command`。

1. 在「模型配置」设置 Jev 或 Laya。Jev 默认使用官方 `https://api.typesafe.ai/v1/systemone`，默认模型 `jev-1.13.0`；使用自己的 Key。Laya 本地运行不需要 Jev Key。
2. 在「数据集」保留默认摩托车题库，或导入自己的 JSON 文件。[三题样例](examples/decision-sample.json)、[格式说明](docs/dataset-format.md)和 [JSON Schema](examples/dataset.schema.json)可直接参考。
3. 在「单题实验」检查一道题的输入、输出、答案分布与判分。
4. 在「批量对照」选择分类、题型、数量、种子、模型、模式与并发。先预览样本和调用数，再开始运行。可以停止、检查错题、重开历史，并导出结果。

建议先测 20 题，再扩大到完整数据集。云端调用可能产生费用；应用不自动重试，认证失败会停止余下调用。

## 导入自己的决策问题

导入的是一个完整 JSON 数据集，必须给出标准答案，才能比较模型是否选对。示例：

```json
{
  "schemaVersion": 1,
  "name": "客服分流",
  "instructions": "依据诉求，把用户交给合适的团队。",
  "questions": [
    {
      "id": "ticket-1",
      "type": "single",
      "question": "用户反馈订单已付款，但一周仍未发货。应转交哪个团队？",
      "options": { "A": "售前咨询", "B": "订单履约", "C": "账号支持" },
      "answer": ["B"],
      "category": "客服"
    }
  ]
}
```

支持 `single`、`multiple`、`boolean` 三种题型；选项为 A 起始的 2–7 个连续字母键。每个数据集最多 10,000 题、导入请求最多 8 MiB。未知字段、重复题号、无效答案与超长文本会拒绝整个导入，原有数据保持不变。标准答案与解析只用于本地判分，不发送给模型。详细规则见[数据格式说明](docs/dataset-format.md)。

自定义数据默认使用通用选择指令，可以通过数据集 `instructions` 指定业务规则；摩托车数据保留法规与安全驾驶指令。实验中的补充指令非空时会替换数据集默认指令。运行中不能切换数据集；结束后可以选择其他数据开始新实验，历史记录保留当时的数据快照。

## 模式与判分

| 模式 | 如何生成选择 |
| --- | --- |
| Choice | 单选 / 判断选择唯一答案；多选枚举全部非空候选集合，最多 127 个。 |
| Noul | 判断题评估命题是否正确；单选逐项判断后取最高值，多选按阈值选中。 |
| Score | 每项按五级尺度评分；单选取最高值，多选按归一化评分阈值选中。评分不是答对概率。 |
| 并行对照 | 一次请求包含三个原语，以 Choice 为主结果，同时展示 Noul / Score 的选择与分歧。 |

「模式指南」还提供并行问题、置信门控、复合评分、意图路由等组合示例，可以自行编辑 `state` 和 `questions`。自由实验没有标准答案，不计入批量正确率。

多选必须完整选对，漏选或多选都算错。正确率 = 完全选对数 ÷ 成功返回有效答案数；连接失败、认证失败、响应格式错误另计。保留阈值另算覆盖率与保留正确率；Jev 和 Laya 的原生 `confidence` 不作为相同含义的指标直接比较。

## 怎样比较 400 题的总耗时

选择同一数据集和筛选条件，数量设为 400，勾选 Jev 与 Laya，选择同一模式与并发，然后开始。若筛选后不足 400 题，预览会显示实际可用数量。

应用按「模型 / 模式」分组**顺序运行**，每组分别使用相同题目顺序和并发上限（1–4），不会把等待其他组的时间计入这一组。结果展示：

- **整批总耗时 `wallMs`**：从该组开始，到已发送请求全部返回、判分并保存后的实际经过时间，包含网络和本地处理。
- **请求耗时合计 `requestMs`**：所有已尝试请求的耗时之和，包含失败请求。并发请求会重叠，这个合计不能代替实际总耗时。
- **尝试 / 计划、成功 / 失败、状态**：两组都完整成功、样本数和并发相同，才展示完成耗时差与倍数。失败、取消或中断的组不能作为完整答题速度比较；旧历史没有计时信息时显示未知。

整次实验总耗时也会显示。固定顺序、网络波动、服务冷热状态与本机负载仍可能影响结果，重复实验时应一并考虑。JSON 导出包含分组计时、数据集指纹和题目快照；逐题 CSV 与汇总 CSV 便于后续统计。

## 本地 Laya

在「模型配置」点击「准备并启动 Laya」。需要先安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)，首次准备需要联网下载 Python 环境、依赖和 `multilingual` 权重。项目固定安装 `laya[serve]==0.3.21`，默认准备 Python 3.12；已有项目环境会复用。

本地服务在 `http://127.0.0.1:8011/v1/systemone`，使用 `.venv-laya` 与 `.local/cache/`。本项目的启动按钮使用 POSIX shell，适合 macOS / Linux；其他环境可在模型配置中连接已有的兼容 HTTP 服务。中文测试默认使用 `multilingual`。多选 Choice 的候选集合较长，可能遇到 Laya 的 token 预算限制，可同时用 Noul 检查。

## 本地数据与验证

Key 默认仅存在于服务内存；勾选「在这台电脑记住 Key」才写入权限为 `0600` 的 `.local/config.json`。Key 不放入浏览器本地存储、请求预览或结果导出，接口地址改变会清除原 Key。

导入数据、实验记录、人工图片描述、配置和模型缓存保存在本机；`.local/`、`.venv-laya/`、环境变量文件与本地截图均排除在 GitHub 提交之外。导入文件不会自动上传到 GitHub。启动测试时，所选题干、选项和生效指令会发给配置的模型服务；本地 Laya 则由本机处理。自行备份 `.local/` 时，若选择过记住 Key，备份中也可能包含 Key。

```sh
npm test
npm run check
```

自动测试覆盖格式验证、原子保存、数据集隔离与恢复、答案不泄漏、判分、抽样、HTTP 协议、配置保密、停止边界和分组计时。测试模拟服务用于验证程序行为，不代表真实模型表现。通用数据集与计时验证见 [2026-10-02 记录](docs/verification-2026-10-02.md)；历史实测保留在 [2026-10-01 记录](docs/verification.md)，其中结论只适用于记录中的版本和样本。

参考：[Jev API](https://docs.typesafe.ai/api)、[原语](https://docs.typesafe.ai/primitives/choice)、[组合模式](https://docs.typesafe.ai/patterns/fan-out)、[Laya 项目](https://github.com/NandhaKishorM/laya)。
